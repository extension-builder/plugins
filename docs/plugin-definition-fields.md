# Joomla 6 plugin changes by JCB definition field

This is the transfer guide for the authored changes in Plugins PR #1. The
`plg_*` trees are source references during this migration, not regenerated Joomla
6 installation packages. Their providers, installer scripts, and API Routes
class are retained exactly as they were at base commit `8fde47e`. Build packages
with the paired Joomla 6 compiler after applying the authored changes below.

The complete maintained JCB definition export is not present in this repository.
The guide therefore identifies existing fields and exact changed methods, not
database IDs, a new import package, or an automatic migration. Match each entry
to the maintained plugin record by its group and name.

## Field ownership

| JCB field or generated part | Treatment |
| --- | --- |
| Class Header (`head`, controlled by `add_head`) | Add the references needed by the changed authored methods. Retain the definition's existing Joomla Power references, aliases and import resolution. If the header comes from the selected Class Extends record, preserve that arrangement; do not overwrite a shared header with a generated file's import list. |
| Properties & Methods (`main_class_code`) | Replace only the named authored methods below; preserve the other properties, methods, comments, and placeholders. Copy method declarations and bodies, not a PHP file, namespace, class declaration, or outer class braces. |
| Property and method selections (`property_selection`, `method_selection`) | Preserve existing choices. These selectors insert catalogue code into the body editor; changing a catalogue entry alone does not replace an already stored handler. Review the stored body after editing it. Do not add generated subscriber methods to the selections. |
| Install script snippets (`php_script_construct`, `php_preflight_*`, `php_postflight_*`, `php_method_*` and their `add_` flags) | No changes are required by this plugin-definition migration. Preserve existing enabled snippets and flags exactly. The compiler owns lifecycle method declarations, constructor/adapter handling, version checks, cleanup wrappers, interface declaration and returned installer instance. |
| Provider and plugin class wrapper | Generated by JCB. Do not copy providers, dispatcher constructor arguments, `final class`, or `implements SubscriberInterface` into authored fields. |
| Default native subscription map | Generated by the Joomla 6 compiler for standard native `on...` handlers. Do not add a duplicate `getSubscribedEvents()` method to the nine content definitions or the API Routes placeholder definition. Existing deliberate compiler-hook and console maps remain unchanged. |

## Privacy Compiler definition

For `extension / componentbuilderprivacycompiler`, use
[ComponentbuilderPrivacyCompiler](../plg_extension_componentbuilderprivacycompiler/src/Extension/ComponentbuilderPrivacyCompiler.php).
This plugin's authored methods generate component code; those emitters are the
source to change, not the generated component helper.

| Field | Exact authored change |
| --- | --- |
| `head` / Power setup | No new top-level import is required by this change. Keep the existing compiler/utility imports and Power references. |
| `main_class_code::setPrivacyExportRequest` | Replace the method with the reviewed emitter. Target 6 obtains `DatabaseInterface` through the Joomla container, uses `createQuery()`, and creates native privacy export Domain, Item and Field objects. Preserve all unrelated emitter logic. |
| `main_class_code::setPrivacyRemoveData` | Replace the method with the reviewed emitter. Target 6 uses the native database lookup and `createQuery()` while retaining its removal/anonymization logic and helper arguments. |
| `main_class_code::isJoomlaSixTarget` | Append the reviewed method after the existing emitter methods. It checks `CompilerFactory::_('Config')->get('joomla_version', 3)` for target 6; the host Joomla version must not select generated APIs. |
| Existing `getSubscribedEvents()` and `jcb_ce_*` methods | Preserve exactly. These deliberate JCB compiler-hook maps and positional/by-reference contracts are not Joomla content listener adapters. |
| Installer snippets and selection fields | Unchanged. |

Retain the split Power-token strings in the emitters: those tokens are intended
for the later component compilation and must not be consumed while compiling
the compiler plugin itself. Existing Factory, DatabaseInterface and Domain
Power identities stay unchanged. Item and Field are emitted as fully qualified
names because the referenced catalogue has no corresponding maintained Power
entries. Joomla 3–5 output remains unchanged.

## Regeneration and version boundaries

After the authored records are updated, let JCB regenerate the Joomla 6 class
wrappers, native subscriptions, providers and installer lifecycle code. The
checked-in historical infrastructure is not the Joomla 6 build result and must
not be deployed as a substitute for that regeneration.

Keep Joomla 4 definitions separate for the nine content handlers because these
concrete events start in Joomla 5. The handler APIs alone can be shared with
Joomla 5, but this change does not certify a complete Joomla 5 distribution.
Preserve existing Joomla 5 compiler/provider/installer output.

The remaining completion step requires the maintained definition package:
compile the linked plugins and full JCB component, install the generated Joomla
6 packages, and exercise their authoring forms and compiler hooks. Focused
source-fixture tests do not establish that the maintained records were updated
or that complete JCB self-compilation has passed.
